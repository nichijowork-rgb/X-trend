# X-trend

Xの情報を集め、**夜職（ホスト・キャバクラ・歌舞伎町など）の業界把握**と**投稿ネタ探し**に使うツールです。歌舞伎町のネオンをイメージした、PC・スマホ両対応のWebアプリです。

| 対象 | 例 | 1日の目安 |
|---|---|---|
| 夜職 | ホスト、キャバクラ、歌舞伎町 | 30〜50件 |
| 一般の話題 | 雑談に使えるバズ話題 | 約3トピック × 各約5件（計15〜20件） |

## できること
- **収集**: 公式X API（キーワード検索・ホームタイムライン）、Grok（xAI）経由のX検索、投稿URL（URLだけでも保存可）、JSON/CSV取り込み、ブックマークレットによる「おすすめ」画面の取り込み。
- **整理**: ジャンル別（夜職／一般）、スコア・表示回数・いいね・新着順の並べ替え、同じ投稿IDの重複統合、同じ話題のトピックまとめ。
- **表示項目**: 元投稿リンク、投稿ID、投稿日時、数値の取得日時、取得元。分からない数値は「不明」と表示し、0や推測値では埋めません。
- **まとめ**: 日次・週次まとめを自動生成します。Grokが接続されていれば要約もGrokで作り、未接続ならルールベースで集計します。
- **興味なし**: 理由（ロイヤルホスト等の別の意味、VTuber、不要な話題、質の悪い投稿者、やらせ）と一緒に保存し、ツール内の非表示や順位下げに反映します。いつでも取り消せます。**Xのおすすめやフォロー状態は一切変更しません。**
- **保存・復元**: データはSQLiteに保存されるので、再起動しても残ります。手動バックアップ（JSON）と自動バックアップ（世代管理つき）から復元できます。
- **共有**: リンクを知っている人は閲覧専用で見られます。編集には管理者トークンが必要です。

## 表示上の約束
- ランキングは「**取得した候補内の順位**」です。X全体の上位ではありません。
- 公式APIのホームタイムラインは**逆時系列**です。おすすめ欄そのものではありません。
- 実データが未接続の間は**サンプルデータであることを明示**します。

## 安全上の制約
- 投稿・いいね・フォロー・DMは一切行いません。
- Cookieや認証情報の抽出・転送は行いません。ブックマークレットは画面に表示された投稿テキストだけを読み、Cookie・ストレージ・通信APIには触れません（テストで検証しています）。
- APIキーは環境変数でだけ受け取り、画面・APIレスポンス・ログには出しません。

## 起動
Node.js 22.13以上が必要です。依存パッケージはありません。

```bash
cp .env.example .env   # 必要なキーを設定（任意）
npm start              # http://localhost:8787
npm test               # 単体テスト
```

Docker の場合は次のとおりです（`/data` を永続ボリュームにしてください）。

```bash
docker build -t x-trend .
docker run -p 8787:8787 -v x-trend-data:/data --env-file .env x-trend
```

### 環境変数
| 変数 | 用途 |
|---|---|
| `ADMIN_TOKEN` | 公開運用では必ず設定してください。設定すると、閲覧には共有リンク、編集には管理者トークンが必要になります |
| `X_BEARER_TOKEN` | 公式X API（最近の検索・投稿の数値更新） |
| `X_USER_ACCESS_TOKEN` / `X_USER_ID` | 公式X API（ホームタイムライン。逆時系列） |
| `XAI_API_KEY` | Grok（X検索・要約） |
| `DATA_DIR` / `PORT` / `TZ_NAME` | 保存先、ポート、タイムゾーン（既定 `Asia/Tokyo`） |

### 共有リンクの使い方
1. `ADMIN_TOKEN` を設定して起動します。
2. 設定画面で管理者トークンを入力します。
3. 設定画面の「共有リンク」をコピーして渡します。

再発行すると古いリンクは無効になります。

## 「おすすめ」欄の取り込み
公式APIでは「おすすめ」欄そのものは取得できません。育てたアカウントのおすすめを取り込むには、**自分のブラウザで開いたXの画面**をブックマークレットで読み取ります。

1. 取り込み画面からブックマークレットを登録します。
2. x.com の「おすすめ」タブを開いて実行します。
3. アプリの確認画面で「取り込む」を押します。

詳しくは [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md) を参照してください。

## 未決定事項（設定画面で後から変更可能）
- APIの契約・費用上限（`budget.xApiMonthlyReadCap` で月間の読み取り上限を設定できます）
- 週次まとめの件数・実行曜日、日次・週次の時刻（既定：収集 9:00/21:00、日次 23:30、週次 月曜 10:00・30件）
- まとめの配信先・方法（既定はアプリ内のみ。Webhook送信にも対応）

## 構成
- `src/`: サーバー（node:http）、保存（node:sqlite）、重複統合・トピック・興味なし・スケジューラ・まとめ・バックアップ・認証
- `src/integrations/`: X API、Grok、URL、JSON/CSV、ブックマークレット
- `public/`: フロントエンド（ビルド不要のES modules）
- `docs/CONTRACT.md`: モジュール間の契約（APIとデータ形式）
- `test/`: 単体テスト（`npm test`）と E2E（`test/e2e/`）
