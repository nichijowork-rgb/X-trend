# 配信番組サイト（/show/）仕様 v2 段階1〜4（2026-10-31: 画面半分向け・フォルダ型の編成・仕分けモード・縦 1 列の進行／OBS オーバーレイ連動／Grok ボット連携／演出）

> v2 の計画（段階 1〜4）は [SHOW_V2_PLAN.md](SHOW_V2_PLAN.md)。この文書は段階1〜4を実装した時点の仕様（段階2＝OBS オーバーレイは「⑤ OBS 連動」、段階3＝ボット連携は「⑥ Grok ボット連携」、段階4＝演出は「⑦ 演出」）。v1.1 の「候補カード・詳細ビュー」は段階1でフォルダ型に置き換えた。

ダッシュボード（`/`）と同じサイト内に置く、週1回のニュース形式トーク配信用の「台本＋進行」サイト。決定事項はオーナー確定済み（2026-10-16）。

## 前提
- 配信: **毎週 土曜 1:00（JST）、約90分**。出演2人（読み手の割り振りは不要）。
- 事前確認: **前日（金）1:00 に下見、金 22:00 に最終確認**。
- 対象期間（番組週）: **前回配信（前週土 1:00）〜今回配信直前**。データの基準時刻は `posts.json` の `generated_at`（現在時刻ではない）。
- 置き場所: `/show/`（同一リポジトリ・GitHub Pages）。ダッシュボードとは**上部のページ切替タブ**（「ダッシュボード」「番組」）で行き来できる。
- データ: `data/posts.json`（全期間の投稿。番組週は ts で切り出す）、任意 `data/bookmarks.json`（後述）。`data/` は読むだけ。（答え合わせコーナー廃止に伴い `reports.json` は番組サイトでは読まない）
- 個人で集めた投稿: ①URLを手で貼る（複数行可）②Xのブックマーク（`data/bookmarks.json`。下記。ファイルが無い・壊れているときはブックマーク枠を非表示、他は動く）。手入力とブックマークで同じ id は 1 つに統合。
- **ブックマーク（2026-10-16 bot対応済み）**: 形式 `{ generated_at: "…+09:00", bookmarks: [{ id, url: "https://x.com/<user>/status/<id>", bookmarked_at: null | JST日時 }] }`。並びは新しくブックマークした順、毎日 0:23 ごろ更新。
  - `bookmarked_at` は「botが最初に見つけた時刻」（実際より最大1日遅れ）。10/16 より前からのものは null。
  - ブックマークした投稿は表示数が基準未満でも全件 posts.json に入り `in_bookmarks: true`（基準未満は `below_threshold: true` も）。id で posts.json を引いて本文・数値・メディア・カテゴリを表示する。
  - 数値は見つけた時点で固定（以後更新なし）→ カードに「数値はブックマーク時点」と注記。解除してもすぐ消えないことがある。
  - 編成画面の「★ブックマーク」枠: 既定は「bookmarked_at が番組週内」または「bookmarked_at が null で投稿日時（ts）が番組週内」。トグルで「すべて」も表示。過去の配信で読んだものは「使用済み」バッジを付けて下へ。
  - 今週分のブックマーク投稿は話題の自動まとめに含め、話題カードに「★ブックマーク n件」シール。話題性スコアに少し加点（1件ごと +10%、最大3件分）。
- 保存: 編成・メモ・進行（済など）・整理（片付け・ゴミ箱）・手入力URL・話題辞書は**ブラウザ内（localStorage）に自動保存**＋JSON 書き出し/読み込み。公開ファイルには書かない。

## 番組構成（既定・時間は編集可。2026-10-16 改定）
| 既定時間 | コーナー | 色 |
|---|---|---|
| 45分 | メイン3トピック（各約15分。**夜職の話題だけ**） | 赤 |
| 30分 | カテゴリ別ニュース（ホスト／キャバクラ／歌舞伎町／夜職その他から選択） | ジャンル色 |
| 15分 | 雑談（一般のバズ） | クリーム |

- オープニング・中休み・今週の答え合わせ・エンディングは**廃止**（タイトルコールは編成画面上部のタイトル欄で足りる）。進行・映す用・振り返り・台本書き出しにも出さない。
- 保存データに旧コーナーがあれば読み込み時に取り除く（スキーマ版 2。旧版の時間は使わず新しい既定、進行の位置は最初に戻し、今あるコーナーの「済」などは残す）。
- **メイン3に一般のバズは入れない**: おすすめは「夜職で2件以上」→「夜職の単発」だけ。一般のバズの話題カードには「メインへ」を出さない。保存済みの編成でメインに一般のバズが入っていたら警告を出し「外す」で外せる（自動では消さない）。

## 話題のまとめ方（類似投稿の統合）
1. **話題辞書**: `{ 話題名, ジャンル, 言葉[] , 関係者[]（店名・源氏名・@アカウント） }`。本文・matched_terms・ユーザー名に一致した投稿を同じ話題に。初期辞書例: 「ホストコール」← シャンパンコール/コール/ラスソン/マイク、など数件を用意。画面で追加・編集。
2. **自動提案**: 辞書に入らない投稿は本文の類似度（文字bigram等）＋同一アカウント・同一関係者でまとめ候補を作り「同じ話題かも？」として提示 → 採用/分割。
3. **手動**: 話題の結合・投稿の移動・話題名の変更。
- 話題ごとに 投稿数・合計インプレ・最大インプレ投稿・伸び（最大の伸びペース）を表示し、**話題性スコア**で並べる。メイン3本の候補は夜職の話題からスコア上位を提案。

## 画面
### ① 編成（準備）＝ フォルダ型（Finder 風。v2 段階1）
基準は **Windows の画面半分（960×1040）**。1280px・全画面（1920）・スマホ（375）でも崩れない。

- **上の帯**: 「10/31(土) の編成」・投稿数・まとまり数、**配信タイトル**（自動「【番組名】メイン1／メイン2／メイン3」。編集可・「自動に戻す」）、**常設の検索**、［↶ 元に戻す］［↷ やり直す］［仕分けモード］［チェック：下見/最終確認 ▾］［ツール…］（番組名・書き出し/読み込み・URL の追加・話題辞書・持ち越し・カード/埋め込み切替）。
- **左: フォルダの木**（約 260〜300px。件数つき・開閉可）
  - 番組構成: **メイン1 / メイン2 / メイン3**（それぞれ話題 1 つ・夜職のみ。空き枠は「空き」）／**メイン候補**（メイン1〜3に入れる前の置き場・夜職のみ）／カテゴリ別ニュース／雑談（一般のバズ）
  - まとまり（話題）: **夜職**・**一般のバズ**（ジャンル色。開くと各まとまりがフォルダとして並ぶ）
  - **受信箱（未整理）**: どのまとまりにも・番組構成にも入っていない今週の投稿
  - **★ブックマーク**（既定は今週の分。「すべて」に切替。前の配信で読んだものは「使用済み」）／**NEW**（前回のチェックポイント以降の投稿）／**片付け**／**ゴミ箱**
- **右: フォルダの中身**（行リスト。1 行 56px・仮想スクロールで見えている分だけ描く）: ⋮⋮（つまみ）・チェック・ジャンル色・本文 1 行（まとまりは名前）・@アカウント・インプレ・★・入っている場所（メイン1 など）・NEW・「…」。行を選ぶと**プレビュー**（X 埋め込み。失敗時は自前のカード）。**1400px 未満は一覧⇄プレビューの切替**（プレビュー上部に「← 一覧へ」）、**1400px 以上は 木｜一覧｜プレビュー の 3 列**。760px 以下は木を「≡ フォルダ」の引き出しに。
- **プレビュー**: 投稿＝埋め込み・ジャンル（上書き）・移動先…・まとまりにする・片付け・削除・X で開く。まとまり＝名前（ダブルクリックで変更）・ジャンル・数字・話題性・入っている場所・「同じ話題かも？」の採用/バラす・**台本**（リード文の自動下書き・話すポイント）・代表投稿の埋め込み。番組構成のフォルダでは時間（分）とコーナーのメモ。
- **検索**: 上部に常設。本文・@アカウント・まとまり名・matched_terms を**スペース区切り AND** で今週の全投稿（＋自分で追加した投稿）から。結果も同じ行リストで、そのままドラッグ・一括操作できる。Esc で消す。
- **ドラッグ＆ドロップ**（pointer events で自作。HTML5 DnD は使わない。マウスは行を押して少し動かす／タッチは「⋮⋮」をつまむ）
  - 投稿（複数可）→ まとまり: 移動（元のまとまりから外れる）
  - 投稿 → 番組構成: その投稿の「単発まとまり」として入る（すでにまとまりに入っていれば**そのまとまりごと**）
  - まとまり → 番組構成: 追加。メイン1〜3 に入っていた話題は**メイン候補へ押し出し**（メイン同士は入れ替え）。カテゴリ別・雑談・メイン候補の中は行の上に落として**並べ替え**
  - まとまり → まとまり: 結合。投稿／まとまり → 受信箱: まとまり・番組構成から外す。→ 片付け／ゴミ箱
  - 置けるフォルダを点線で、真上のフォルダを黄色で強調。影に「n件」のバッジ。**Esc でキャンセル**。一覧・木の端では自動スクロール
  - 一般のバズはメイン1〜3・メイン候補に置けない（強調もしない）
  - 代替操作: 「移動先…」（一括操作バー・右クリック・プレビュー・M キー）。絞り込み欄＋上下キー＋Enter で選べる
- **複数選択**: Ctrl/⌘＋クリック、Shift＋クリック（範囲）、チェックボックス、Ctrl+A（表示中の行）。キーボード: ↑↓（Shift で範囲）・Space・Enter（まとまりを開く／プレビュー）・Delete（削除）・Shift+F10/コンテキストキー（メニュー）。選択中は下部に**一括操作バー**（移動先… / まとまりにする / ジャンル変更 ▴ / 片付け / 削除 / 選択解除）。
- **右クリックメニュー**（「…」でも同じ）: プレビュー・フォルダを開く・番組に入れる（メイン1〜3・メイン候補・カテゴリ別・雑談）・移動先…・まとまりにする・名前を変える（F2）・ジャンル（5 種）・受信箱に戻す・片付ける・削除・X で開く。上下キーで選べる。
- **新しいまとまり**: 「＋新しいまとまり」で空のフォルダ（名前・ジャンル）。選んだ行から「まとまりにする」でも作る（投稿は移動、まとまりは結合）。名前は左の木のダブルクリック・プレビューのダブルクリック・F2 で変更（空にすると自動の名前に戻る）。
- **ジャンル変更**: 投稿・まとまり単位で ホスト／キャバクラ／歌舞伎町／夜職その他／一般のバズ に上書き（右クリック・「…」・プレビュー・一括操作バー・仕分けモード）。**投稿の上書きは投稿 ID で保存し、翌週以降も有効**（元のジャンルに戻すと上書きは消える）。まとまりの上書きはその週だけ（無ければ中の投稿の多数決）。上書き一覧は書き出しファイルの `genreOverrides` に入り、「ボットに修正を送る」で `genre_overrides` としてボットへ返す。
- **元に戻す / やり直す**: Ctrl+Z / Ctrl+Shift+Z・Ctrl+Y、上の帯のボタン、操作直後のお知らせの「元に戻す」。ドラッグ・移動・ジャンル変更・作成・名前変更・片付け・削除・戻す・辞書・時間・チェックポイント・読み込みが対象（直前 40 回まで。文字の入力中の Ctrl+Z は入力欄の取り消し）。
- **一般のバズの絞り込み**: 受信箱と「まとまり：一般のバズ」は既定で**おすすめ上位 30 件**だけ（話題性スコア＝インプレの対数・伸び・★。`config.js` の `PLAN_V2.generalRecommendN`）。「すべて表示」に切替可。ボットが投稿に `show_pick: true` を付けたら最優先でおすすめに入る（段階3: 理由 `show_pick_reason` を行・プレビューに表示）。
- **仕分けモード**: 受信箱・検索結果・任意のフォルダの行を 1 件ずつ大きく（埋め込み）表示。キー **1** メイン候補／**2** カテゴリ別／**3** 雑談／**G** ジャンル（夜職⇄一般。下のボタンで 5 種から選べる）／**X** いらない（片付け）／**→** 保留して次／**←** 前／**Esc** 終了。各操作は元に戻せる（Ctrl+Z）。上に「n / 全件・残り m件」と進み具合のバー。一般のバズは 1（メイン候補）に入らない。
- 整理（片付け・ゴミ箱）・チェックポイント（NEW）・書き出し/読み込み・ブックマーク・カード/埋め込み切替・メイン3は夜職のみ・持ち越し・話題辞書・URL の追加は v1.1 から引き継ぐ（置き場所は上記のフォルダ・ツール）。
### ② 進行（配信中・画面半分向けの縦 1 列）
- 上に**細い進行バー**（コーナーごとの区切り・話題ごとの小さな帯。済＝濃い／現在＝白枠／飛ばした・来週へ＝斜線／残り＝薄い。押すとそこへ移動）→ **現在の話題名（大）**とコーナー名・n/of → タイマー（全体の経過／コーナー残り・押し巻き）・［配信開始］/［リセット］→ 中央に代表投稿（X 埋め込みが既定）・リード文・関連投稿 → **下にボタン固定**（← 戻す／飛ばす／来週に回す／読んだ →）。
- キーボード: →/Enter 読んだ、← 戻す、S 飛ばす、L 来週へ、**J/↓ 次の投稿を映す・K/↑ 前の投稿を映す**、Shift+1〜6 演出。1400px 以上は右に番組全体の一覧も出す。
- **投稿カードは常に表示（2026-11-08 オーナー確定）**: 「投稿カード：表示中／隠し中」の切り替えは廃止。OBS の投稿カードには常に「今の投稿」が出る（`live.cardVisible` は常に true。古い保存データの false も true として読む）。
- **上部固定のヘッダー（2026-11-07）**: 細い進行バーと赤いヘッダー（コーナー名・n/of・話題名 1 行で省略・全体の経過／コーナー残り・押し巻き・OBS の状態ピル・［開く窓］・配信開始/リセット）を `position: sticky` で常に上に出す（下の「読んだ」ボタン列も固定）。コンパクトにして、画面半分（960×1040）でも投稿の表示領域を広く取る。
- **リード文はトグル**: 既定は閉じて「▸ リード文」の 1 行だけ（Grok の印もここ）。開閉は localStorage `xtrend-show-lead-open`。
- **投稿のグリッド**: 700px 未満は 1 列、700px 以上（画面半分の 960 など）は 2 列（1 列 約 440px）、1400px 以上は 3 列。2 列・3 列でもドラッグで並べ替え（置く位置は左に黄色の線）・×・…・映し中の枠が使える。画像も同じグリッド。
- **投稿を開く専用ウィンドウ**: 「X で開く」などの X のリンク（進行・編成・振り返り）は、新しいタブではなく名前付きのポップアップ（`xtrend-viewer`。毎回同じウィンドウを使い回し、位置・大きさも合わせ直す）で開く。［開く窓］（進行）か［ツール…］の「投稿を開くウィンドウ」で、位置＝中央／右半分／左半分／全体／数値で指定（左・上・幅・高さ）。Chrome の Window Management API（`window.getScreenDetails`。初回に許可の確認）が使えれば「表示する画面（モニター）」を選べる（使えなければ数値指定とこのウィンドウの画面）。設定は localStorage `xtrend-show-viewer`。ブロックされたら「アドレスバー右のアイコンから許可」と案内。`show/js/viewer.js`・`views/viewerui.js`。
  - **埋め込みのクリック受け**: 埋め込みの中のクリックはページで受け取れないので、進行の埋め込みの上に透明なクリック受けを重ねる（既定オン）。クリックで「今の投稿」にし、設定「クリックしたらこのウィンドウでも開く」がオンなら専用ウィンドウでも開く。各カードの「埋め込みを操作」でそのカードだけ受けを外して動画再生などを直接できる（もう一度押すか、別の投稿に移ると戻る）。編成のプレビューの埋め込みにはクリック受けを付けない。
- **話題の投稿（2026-11-07 改修）**: 代表投稿を含む話題の投稿をすべて 1 つの一覧に出す（最初に 5 件、「残り n件を表示」で全部。開いた状態は話題ごとに覚える）。**投稿は常に X 公式埋め込み**（カード/埋め込みの切替に関係なく。画面に近いものから作り、失敗・データに無い投稿だけ自前のカード）。DOM の並びは id 順のまま CSS の `order` で並べるので、並べ替えても埋め込みを作り直さない（`patch.js` の keep と合わせてちらつかない）。
  - **並び順**: 「インプレ順／古い順」（古い順＝投稿日時の昇順。時系列で読み上げる用。既定はインプレ順。進行の保存 `live.order`）。手で並べ替えると「手動順」になり、インプレ順・古い順を押すと解除（元に戻せる）。
  - **整理**: 各投稿の帯（⋮⋮・番号・映し中・×・…）をドラッグで並べ替え（段階1の pointer events D&D を再利用。マウス・タッチ。埋め込みの iframe にポインタを取られないよう帯から）。置いた先の投稿の位置へ入り、一覧の下の「ここに置くと末尾へ」で末尾。×＝話題から外す（投稿は受信箱へ・データに無い投稿は外す・画像は消す）、…＝話題から外す／この投稿を削除（非表示）／先頭へ（代表にする）／末尾へ。どれも Ctrl+Z で戻せる（編成と共通の履歴）。並べた順は番組週の `postOrder[話題id]` に保存し、**先頭の投稿が代表投稿**（編成のまとまりの中の並び・プレビューの代表投稿・映す用・振り返り・書き出しにも反映）。

**送り方**
- 送り手は［進行］画面と［OBS］（セットアップ）画面を開いているタブだけ。進行状態が変わったとき（`publishLive` から。コーナー・話題・投稿カード・進み具合）に `seq` を進めて送り、**5 秒おきに同じものを再送**（後から開いたパーツ・OBS の再起動が追いつく）。
- 送り先は 2 つ: ① 同じブラウザ内の `BroadcastChannel('xtrend-show-overlay')`（プレビュー用）、② OBS WebSocket（接続済みのとき）。
- OBS へは obs-websocket v5: 接続 → Hello(op 0) → Identify(op 1。`authentication = base64(SHA256(base64(SHA256(password + salt)) + challenge))`、crypto.subtle) → Identified(op 2) → Request(op 6):
  `{ requestType: 'CallVendorRequest', requestId: 'xt-n', requestData: { vendorName: 'obs-browser', requestType: 'emit_event', requestData: { event_name: 'xtrend-show', event_data: ペイロード } } }` → RequestResponse(op 7)。
  OBS が全ブラウザソースに `window` の CustomEvent `xtrend-show` を送り、パーツは `addEventListener('xtrend-show', e => e.detail)` で受ける（`detail` は文字列でもオブジェクトでも読む）。
- 受け手は `sid`（送り手の起動ごとの id）と `seq` で古いもの・再送を見分ける: 同じ sid なら seq が大きいときだけ、sid が変わったら（進行画面を開き直した）`at` が新しいときだけ使う。

### 編成: まとまりの中身・URL で追加・木からドラッグ（2026-11-08 追加）

### ⑨ 対象期間（台本づくりのデータ収集期間。2026-10-31 追加・オーナー確定）

### ⑩ 台本ファイルの取り込み（xtrend-script v1。2026-10-31 追加）
監督者が作った台本（md から作る JSON）を［ツール…］→「台本ファイルを取り込む」（ファイルを選ぶか貼り付け）で番組サイトへ入れる。`show/js/scriptimport.js`。

```jsonc
{ "app": "xtrend-script", "v": 1,
  "title": "【週刊ヨルニュース】…",                 // 任意。あれば配信タイトルに
  "week": "2026-10-31",                              // 番組週のキー（土曜の配信日）
  "range": { "from": "2026-10-24T01:00:00+09:00", "to": "2026-10-31T06:41:48+09:00" },   // 任意。あれば対象期間をカスタムに
  "corners": {
    "main":     [ { "name": "…", "genre": "ホスト", "post_ids": ["…"], "lead": "リード文", "notes": "経緯・切り口・注意（自分用メモ）" } ],   // 最大 3。順にメイン1〜3
    "category": [ { …同じ形… } ],                   // 最大 30
    "chat":     [ { …同じ形… } ] },                 // 最大 30
  "hold": [ { "name": "…", "post_ids": ["…"] } ] }   // 任意。保留フォルダへ
```
- 項目: `name` 必須（80 字）。`genre` はカテゴリ名（ホスト／キャバクラ／歌舞伎町／夜職その他／その他）かジャンルキー。無い・分からないときは投稿の多数決。`post_ids` は数字の文字列（300 件まで）。`lead` 2000 字・`notes` 4000 字。
- **確認**: 取り込む前に一覧（取り込み先の番組週・タイトル・対象期間・各項目の枠／名前／ジャンル／投稿数／データに無い件数／前に取り込んだものの更新か／今その枠にある話題をどうするか・保留）を出し、［取り込む］で実行。不正なファイルは日本語のエラー（JSON でない・xtrend-script でない・版が違う・番組週が不正・corners が無い・話題が 1 本も無い）、読み飛ばした項目は注意として一覧に出す。文字はすべて textContent。
- **動作**（1 回の編集＝ Ctrl+Z で一度に元に戻せる。保存・書き出しに入る）:
  - `week` の番組週に切り替え、`range` があれば対象期間をカスタムに、`title` があれば配信タイトルに。
  - 各項目を「手で作ったまとまり」（`m:s-<週と名前から作る id>`。`source: 'script'`）として作る。投稿は手で移したのと同じ（`overrides.moves`）。posts.json に無い id は `missing` に持ち、フォルダの中に「データに無い投稿」として出す。
  - メイン1〜3・カテゴリ別・雑談へ順に置く。メイン枠に別の話題があればメイン候補へ退避、カテゴリ別・雑談の既存の話題は後ろに残す。片付け・ゴミ箱にあった同じ話題は戻す。
  - `lead` はリード文（台本の lead 欄）、`notes` はその話題の「話すポイント（自分用メモ）」。
  - `hold` は番組週の `scriptHold` に入り、その投稿は保留フォルダへ（理由「台本：◯◯」。手で置いた話題の投稿・戻した例外は除く）。
  - **同じファイルを 2 回取り込んでも重複しない**（名前＋週が同じなら同じ id。中身を更新し、台本から外した投稿は外れる）。

### ⑪ YouTube ライブのコメント（流れるコメント・固定コメント。2026-11-14 追加・オーナー確定）
YouTube Data API v3 を **読み取りだけ**（API キー。OAuth・Cookie なし。投稿・削除・BAN などの書き込みは一切しない）で使い、配信のコメントを OBS の「流れるコメント」パーツ（`overlay.html?part=comments`・1920×1080 全面。`part=all` にも入る）に流す。`show/js/ytchat.js`（取得・読み方・NG・設定・メッセージ）、`show/js/lanes.js`（列の割り当て）、`show/js/views/chatui.js`（進行のパネル・設定）。

**データの流れ**
1. ［進行］の「コメント」パネルで配信の URL を入れて［開始］。URL は `watch?v=`・`youtu.be/`・`/live/ID`・`/shorts/ID`・`studio.youtube.com/video/ID/livestreaming`・`m.youtube.com`・11 文字の ID を受け付ける（`parseVideoId`）。
   - **URL を空にして［開始］すると、登録したチャンネルの今の配信を自動で探す**（下の「チャンネルから自動で探す」）。
2. `videos.list?part=liveStreamingDetails&id=…&key=…`（1 単位）で `activeLiveChatId` を取る。無い＝配信が始まっていない・終わった・チャットがオフ・URL 違い → 止めて案内。
3. **取得方式（既定「自動」）**: まず **プッシュ型** `liveChat/messages/stream?liveChatId=…&part=snippet,authorDetails&maxResults=200&pageToken=…&key=…`（サーバーが開いたままの接続で、`LiveChatMessageListResponse` を JSON 配列の要素として少しずつ送ってくる。1 接続 5 単位）につなぐ。本文は `ReadableStream`＋`TextDecoder({stream:true})`＋要素ごとの取り出し（`createJsonArrayParser`。文字列の中の `" \ [ ] { }` は数えない。UTF-8 の文字の途中で切れても大丈夫）。エラーも `[{"error":{…}}]` の形（4xx）で、配列で包まれた本文も同じ判定で読む。`alt=sse` は使えない。
   - **最初の要素は開始前のコメント＝一覧だけ・流さない**（数秒おきと同じ）。以後の要素は流す。`nextPageToken` を覚え、接続が切れたら **続きから**（`pageToken`）つなぎ直す。失敗が続けば 0→1→2→5→10→15 秒、**接続は 5 秒に 1 回まで**。**120 秒なにも届かなければ**切ってつなぎ直す（見張り）。
   - **数秒おきへ自動で切り替える**（状態に「取得中（6秒ごと）※プッシュが使えないため」）: 最初の接続で通信・CORS の失敗（TypeError）／HTTP 404・405・501／理由の分からない 4xx／30 秒の間に要素なしで 3 回切れた（「※プッシュが続かないため」）。上限・配信なし・キーの設定（理由が分かるもの）は数秒おきと同じく止める。混雑（5xx・429）はつなぎ直す。
   - 数秒おき: `liveChat/messages?…`（見積もり 5 単位/回）を `max(pollingIntervalMillis, 取得間隔)` ごと（取得間隔 5・6・8・10・15 秒。既定 6）。切り替えたときは続き（pageToken）から。
   - 設定「取得方式」: 自動（プッシュ→だめなら数秒ごと）／数秒ごとのみ。状態の表示は「取得中（プッシュ）・n件」「取得中（6秒ごと）・n件」「取得中（6秒ごと）※プッシュが使えないため・n件」。
4. fetch は `{ referrerPolicy: 'origin', credentials: 'omit' }`（ページは `no-referrer` なので、キーの「ウェブサイトの制限」のために origin だけ送る）。
5. 読む種類: `textMessageEvent`（本文）／`superChatEvent`（コメント＋金額。色は tier）／`superStickerEvent`（「スーパーステッカー ¥500」）／`messageDeletedEvent`（一覧・固定・画面から消す）／`userBannedEvent`（その人のコメントを全部消す）。ほかは無視。名前は `displayName` のまま（ふつう「@ハンドル」）。アイコンは https の `yt3.ggpht.com`・`yt4.ggpht.com`・`yt3.googleusercontent.com`・`lh3.googleusercontent.com` だけ（ほかは頭文字の丸）。配信者・モデレーターは一覧に印。
6. 新しいコメントは `type: 'chat'` のメッセージで送る（OBS は接続中なら emit_event、同じブラウザは BroadcastChannel。イベント名は `xtrend-show` のまま、進行状態の `type: 'state'` とは別の sid/seq）:
```jsonc
{ "v": 1, "type": "chat", "sid": "…", "seq": 12, "at": 1790000000000,
  "add": [ { "id": "LCC.…", "kind": "text|super|sticker", "text": "60 文字まで（超えたら …）", "name": "@handle", "icon": "https://yt3.ggpht.com/…|null", "amount": "¥1,000", "color": "#ffca28|null", "at": 1790000000000 } ],
  "remove": ["LCC.…"],                       // 削除・BAN・画面から消す・NG になったもの
  "pin": { "id": "…", "kind": "text", "text": "140 文字まで", "name": "@handle", "icon": null, "amount": "", "color": null } | null,
  "cfg": { "band": { "x": 0, "y": 660, "w": 1920, "h": 248 }, "lanes": 4, "size": 34, "speed": 8,
           "pin": { "x": 655, "y": 600, "w": 1170, "size": 34, "lines": 2 }, "flow": true } }   // 帯（流れる範囲）と固定コメントの箱。レイアウト調整で変える
```
   - 受け手は add を id で 1 回だけ（覚えるのは 600 件まで）、**30 秒より古いものは流さない**（後から開いたソースが昔のコメントを流さない。送り手と時計が 1 分以上ずれていれば送った時刻を基準に）。remove・pin・cfg は毎回反映（同じ送り手の古い seq は pin・cfg を変えない）。
   - 送り手は取得中・固定中・見本の間、5 秒おき（`RESEND_MS`）に `{ add: [], pin, cfg }` を再送（後から開いたソースにも固定・設定が届く）。
7. 取得は **画面（ルート）に関係なく続く**（編成へ移っても流れる）。開始したとき、OBS の設定が有効（自動でつなぐ）ならつなぐ。

**流れ方（オーバーレイ）**: コメントは **流れる範囲（帯 `band`）の右端から入り、左端で消える**（帯の外は見せない）。速さは帯の幅 ÷ 速さ秒（既定 8 秒）。帯は既定 x 0・y 660・幅 1920・高さ 248 を 4 列（1 列 62px。下端 908＝トピック帯 915 のすぐ上）。前のコメントのお尻が帯に入って 40px 進んだら同じ列に次を出せる（同じ速さなので追いつかない）。空いている列を上から選び、空きが無ければ待つ（40 件まで。あふれたら古いものを捨てる）。本文（既定 34px）の太字・白・黒の縁取り、その下に 22px の丸いアイコン＋名前 17px。スーパーチャット・ステッカーは色つきの帯＋金額。`?motion=off`・OS の「動きを減らす」では流さずに列の左寄り（帯の左端＋40）でフェードイン・アウト。URL の `&top= &lanes= &laneh= &size= &speed=` で上書きできる（top＝帯の y、lanes・laneh＝帯の高さ＝列 × 列の高さ。確認・微調整用）。古い保存（`top・lanes・laneH`）は帯 `{ x: 0, y: top, w: 1920, h: lanes × laneH }` に移す。
- **固定コメント**: 一覧の［固定］で、固定コメントの箱（`pin`。既定 x 655・y 600・幅 1170・文字 34px・2 行まで。高さは中身しだい＝48px のアイコン・名前・本文を行数まで、超えたら …）に出す。暗い半透明・ピンク赤（#ff3c6e）の枠・左上に「固定中」。流れるコメントより上。**固定中は、箱の実際の位置・高さと重なる列（横にも重なるとき）に新しいコメントを入れない**（流れているものはそのまま箱の裏を通る）。
- 固定は保存し、**固定してから 3 時間以内なら開き直しても復元**（先週の固定が急に出ないように）。

**進行のパネル**（固定ヘッダーの下。「コメント ▸」で開閉、開閉は localStorage `xtrend-show-ytchat-open`）
- 閉じているとき: 1 行の状態（未設定／接続中…／取得中・n件／やり直し中：理由／停止／エラー：理由）と［開始］／［停止］。
- 開いたとき: 配信の URL（空ならチャンネルから探す、と入力欄と下の 1 行に案内）・［開始］／［停止］・「画面に流す」・［レイアウト調整］（オフでも取得は続く。オンに戻すまで流さない）・［⚙ 設定］・固定中の表示（［固定を外す］）・一覧（新しいものが上、約 6 行の高さでスクロール、最大 300 件。行ごとにアイコン・名前・本文・金額・［固定］／［固定を外す］・［画面から消す］）。
- 取得のたびに画面全体は描き直さない（`refreshChatPanel` が状態の行・固定中・一覧を id ごとの差分で更新。一覧は `data-keep-leaf`）。一覧は保存しない（開き直すと空）。
- **安全のため**: 「画面に流す」のオン・オフ／NG ワード（「、」「,」改行区切り。全角半角・大文字小文字をそろえて照合し、本文と名前を見る。当たったものは一覧で灰色・取り消し線、流さない・固定できない。あとから NG にしたものは画面から消す）／行ごとの［画面から消す］（流れていれば消し、これからも出さない。固定中なら外す）／画面の本文は 60 文字まで／文字はすべて textContent。

**設定**（［⚙ 設定］。localStorage `xtrend-show-ytchat` だけに保存。番組の保存データ・書き出し・ボットへの修正には入らない）: API キー（パスワード欄・`autocomplete="new-password"`・「キーを表示」・［キーを消す］。「AIza」で始まらないものは保存も使用もしない。googleapis 以外には送らず、ログにも出さない）／チャンネル（@ハンドル・URL・UC…）／取得方式（自動・数秒ごとのみ）／取得間隔（5・6・8・10・15 秒。既定 6）／NG ワード／［レイアウト調整を開く］／［見本を流す］（API を使わずに架空の名前のコメントを 10 件、OBS・このブラウザのパーツへ。一覧にも「見本」の印で入る）／使った量（この起動で「約 n / 10,000」）。流れ方の数値（位置・列・文字・速さ）はレイアウト調整の中で入れる。保存の形: `{ key, url, channel, channelInfo, mode, interval, ng, layout: { band, lanes, size, speed, pin }, flow, pin（固定したコメント）, pinnedAt }`。
- 確認用（E2E）: `xtrend-show-ytchat-fast`（取得間隔の最短・プッシュの接続の間隔・探す間隔の ms。ふだんは使わない）。

**使える量**: 1 日 10,000 単位（日本時間の 16〜17 時ごろに戻る）。数秒おきは取得間隔 6 秒で 1 時間に約 3,000（＝約 3 時間）、8 秒で約 2,250、10 秒で約 1,800。プッシュは 1 接続 5（つなぎ直すたび）なので、つながっている間はずっと少ない。チャンネルから探すとき: channels.list 1（初回だけ。結果は保存）・playlistItems 1＋videos 1（30 秒ごと）・見つからなければ search.list 100（5 分に 1 回まで）＋videos 1。どれも「使った量」に入る。

**エラー（日本語で案内）**: 今日の上限（quotaExceeded・dailyLimitExceeded）→止める／配信が始まっていない・終わった・チャットがオフ・URL 違い（liveChatEnded・liveChatNotFound・liveChatDisabled・activeLiveChatId なし・offlineAt）→止める／API キーの設定（keyInvalid・API_KEY_INVALID・accessNotConfigured＝API が有効でない・ウェブサイトの制限で拒否）→止めて「API キーの設定を確認」／通信の失敗・混雑（5xx・rateLimitExceeded）→ 2→5→10→20→30 秒でやり直す（止めない）。

**チャンネルから自動で探す**（`createLiveFinder`）
- ［⚙ 設定］の「チャンネル」に `@ハンドル`・`https://www.youtube.com/@ハンドル(/live)`・`/channel/UC…`・`UC…` を入れる（リポジトリにチャンネルは書かない。オーナーがこのブラウザで入れる）。
- 配信の URL を空にして［開始］→ ① `channels.list?part=snippet,contentDetails&forHandle=@x`（か `id=UC…`。1 単位）でチャンネルの ID とアップロードの再生リスト（`contentDetails.relatedPlaylists.uploads`）を取り、設定に保存（`channelInfo`。次からは省く） ② `playlistItems.list?part=contentDetails&playlistId=UU…&maxResults=10`＋`videos.list?part=snippet,liveStreamingDetails&id=…`（2 単位）で「`actualStartTime` があり `actualEndTime` が無く `activeLiveChatId` がある」いちばん新しい配信を選ぶ（予定・終わった配信は選ばない） ③ 無ければ `search.list?part=id&channelId=…&eventType=live&type=video&maxResults=5`（100 単位）＋ videos.list。
- 見つからなければ自動で探し続ける: ②は 30 秒ごと、③は 5 分に 1 回まで、15 分であきらめる。その間の状態は「配信を探しています…（始まってから見つかるまで数分かかることがあります。限定公開の配信は URL を貼ってください）」。
- 見つかったらパネルに「見つけた配信：題名」を出し、`activeLiveChatId` でそのまま取得を始める（videos.list を省く）。URL を入れたときは今までどおりその配信。

**レイアウト調整**（「触りながら調整」。［進行］の「コメント」パネル・［⚙ 設定］・［OBS］タブの［レイアウト調整］。`show/js/views/layouteditor.js`・幾何は `show/js/layoutgeo.js`）
- 1920×1080 を縮小した画面（16:9。画面半分 960px でも、マウス・タッチ・ペンで操作）。後ろに参考の枠（どね貯金・LINE・LINE ID・イラスト・トピック帯・投稿カード。表示の切り替えあり）と、任意で「背景にスクショ…」（ファイルを選ぶか Ctrl+V。長辺 1280・450KB までに縮めて localStorage `xtrend-show-layout-bg` だけに保存。どこにも送らない）。
- 動かせるもの: **流れる範囲**（ドラッグで移動・8 つのつまみで大きさ。列の数 −/＋（1 列＝高さ ÷ 列。列の区切りを点線で表示。1 列 24px 未満にはならない）・文字の大きさ・速さのスライダー）／**固定コメント**（ドラッグで移動・左右のつまみで幅・文字の大きさ・行数 1〜3。高さは中身で決まる）。矢印キーで 1px、Shift＋矢印で 10px。「ぴったり合わせる」（既定オン）で 10px ごと・画面の端・参考の枠の辺・もう一方の箱の辺にそろう（8px 以内）。画面の外には出ない・最小の大きさ（帯 200×30、固定の幅 300）。x・y・幅・高さの数字を表示し、入力もできる。
- 見本: 画面の中に本物のオーバーレイ（`overlay.html?part=comments&preview=1` を iframe で。BroadcastChannel・OBS は聞かず、親の画面から postMessage で設定だけ受け取る）を重ね、見本のコメントが新しい帯の中を流れ、見本の固定コメントが箱に出る（固定の実際の高さもここで測る）。
- 「OBS にも見本を出す」（既定オン）: 調整中の設定・見本のコメント・見本の固定を、OBS（と同じブラウザのパーツ）にも 100ms ごとまでに送る＝ドラッグしながら OBS のプレビューで確かめられる。閉じると本物の固定・流れ方に戻す。
- ［保存］で設定（`layout`）に入れて OBS へ／［キャンセル（開く前に戻す）］／［既定に戻す］（帯 0,660,1920×248・4 列・固定 655,600 幅 1170・34px・2 行。保存するまでは反映しない）。

**API キーの作り方**（設定ダイアログにも同じ案内）
1. Google Cloud（console.cloud.google.com）に Google アカウントで入り、上の「プロジェクトの選択」→「新しいプロジェクト」（「このページを表示するには、プロジェクトを選択してください」と出たら右の「プロジェクトの作成」）で作る（名前は自由。例: yoru-comments）。
2. 作ったプロジェクトを上の「プロジェクトの選択」で選んだ状態で、「API とサービス」→「ライブラリ」で「YouTube Data API v3」を探して「有効にする」。
3. 「API とサービス」→「認証情報」→「認証情報を作成」→「API キー」。できたキーをコピーし、［進行］→「コメント」→［⚙ 設定］の「API キー」に貼って［保存］。

### データの読み方
- `../data/posts.json`・`bookmarks.json`・`show/topics.json`（任意）を `?t=` 付きで最初に 1 回だけ取得。posts が読めなければ `../sample/show/` を読み「サンプル表示中」の帯を出す（映す用は右上に小さく「サンプル」）。
- 番組週は `generated_at`（無ければ最新投稿）を含む「前週 土 1:00 以上〜土 1:00 未満」。ヘッダーで過去の週・来週（持ち越し確認用）に切り替えられる。
- matched_terms の `topic:` はデータ側の話題名としてそのまままとめる。`quote:` は外して言葉として使い、`report:` / `manual` / `inherit:` は使わない。

### 話題のまとめ方（順番）
1. 前週から持ち越した話題 →（段階3: ユーザーが手を入れた話題 → ボットのまとめ。「⑥」参照）→ 2. `topic:` の話題名 → 3. 話題辞書（言葉は1点、関係者は2点。一番多く一致した項目。カタカナの言葉は前後がカタカナだと不一致＝「アルコール」は「コール」に入らない。「夜職のみ」の項目は夜職4カテゴリの投稿にだけ当てる。初期辞書はすべて「夜職のみ」＝一般のバズの「大学を卒業」「選手が引退」は「卒業・引退」に入らない）
4. 残りから「同じ話題かも？」の提案: 本文の文字 bigram の類似（Jaccard 0.34 以上。多くの投稿に出る bigram は無視）→ 同じアカウント（夜職のみ）→ @で言及した相手（夜職のみ）。段階をまたいで鎖状につながらないようにしている。夜職と一般のバズは混ぜない。
5. 手動の上書き: 分割（バラす）・投稿の移動・話題の結合・名前・ジャンル。
- 話題名: 辞書名・`topic:` 名を優先。それ以外は本文から、先頭の【…】タグ・URL・@・絵文字・記号を除いた最初の句（4字以上、最大20字）。本文が【…】だけならその中身、URL だけなら「@アカウント の投稿（本文なし）」。
- 話題性スコア（対数。単発の巨大インプレが勝ちすぎないように）= log10(1＋合計表示＋最大伸びペース×12時間) ＋ 0.6×log2(投稿数)（32件で頭打ち）＋ 0.15×★ブックマーク件数（最大3件）。画面では×10 の「点」。表示数がすべて不明な話題は末尾。重みは `config.js` の `SCORE_WEIGHTS`。
- メイン3のおすすめ: 「夜職で2件以上」→「夜職の単発」→「一般のバズ2件以上」→「一般のバズの単発」の順（`MAIN_SUGGEST_TIERS`）、同じ段はスコア順。
- 候補一覧（「候補」タブ。片付け・削除した話題は除く）: 「まとまった話題」（2件以上・持ち越し・手動・自分で貼った投稿。`GROUPED_MIN_POSTS`）をカードで並べ、単発は「その他の単発投稿（n件）」に折りたたみ（開くと一覧、上の「話題名で探す」で検索、30件ずつ）。「NEW」「自分で追加・ブクマ」で絞ったときは折りたたまない。

### 使い方（オーナー向け・v2）
1. **金 1:00（下見）**: Windows で画面半分にして `/show/` の［編成］。［チェック ▾］→「下見（金1:00）を記録」。左の「受信箱」を開き［仕分けモード］で 1 件ずつ **1/2/3**（メイン候補・カテゴリ別・雑談）、**G**（ジャンル違いを直す）、**X**（いらない）、**→**（保留）。
2. 「まとまり：夜職」を開いて大きな話題を確認し、**左のメイン1〜3 へドラッグ**（入れ替えもドラッグ）。似た投稿はまとまりへドラッグして集める／選んで「まとまりにする」。名前はダブルクリックか F2。
3. 台本: まとまりを選ぶとプレビューに台本欄（リード文の自動下書き・話すポイント）。自分で見つけた投稿は［ツール…］→ URL を貼る。間違えたら Ctrl+Z。
4. **金 22:00（最終確認）**: 「最終確認（金22:00）を記録」。データ更新後に左の「NEW」に増えた投稿が出る。
5. **土 1:00 配信**: （初回だけ）［OBS］タブのガイドどおり OBS の WebSocket を有効にし、パーツ（トピック帯・投稿カード・コーナータイトル）をブラウザソースで貼る。［進行］の右上「OBS：未接続」→ パスワード →［接続］→［テスト表示］で確認（2 回目からは自動で接続）。［映す用↗］は全部入りの確認・ウィンドウキャプチャ用に残してある。［進行］（画面半分で縦 1 列）で「配信開始」→ →/Enter 読んだ、← 戻す、S 飛ばす、L 来週へ。OBS の投稿カードには常に「今の投稿」が出る。
6. 配信後: ［振り返り］で「告知・概要欄用」をコピー。来週に回した話題は翌週の「まとまり」に「持ち越し」で出る。
7. （コメント）配信が始まったら［進行］の「コメント ▸」を開き、配信の URL を入れて［開始］（初回だけ ⚙ 設定で API キー）。読みたいコメントは［固定］、困るコメントは［画面から消す］、荒れたら「画面に流す」を外す。OBS には「流れるコメント」パーツを全面に貼り、投稿カードより下に置く。
8. （段階4）配信中の盛り上がりに合わせて［進行］の「演出 ▸」から拍手・紙吹雪など（Shift+1〜6）。投げ銭のお礼は名前・金額を入れて Enter。
9. （段階3）［ツール…］→「ボット（Grok）に修正を送る」で初回だけトークンを入れて［GitHub に保存］。あとは「自動で送る」（既定オン）で編集のたびに自動で届く（ヘッダーの「ボット送信：済 ◯◯:◯◯」で確認）。トークンを使わないときは［ファイルで保存］。

### 注意・残課題
- 流れるコメント: 既定の固定コメントの箱（x 655〜1825・y 600〜）は投稿カード（x 1330〜1870・y 195〜836）と重なる（カードより下に置くと右側が隠れる）。位置は「レイアウト調整」で見ながら決める。本物の YouTube API（キーの制限・quota・pollingIntervalMillis・stream の接続の続き方）は実配信で確認が必要（E2E は googleapis をモック）。
- 映す用（#onair）の追従は**同じブラウザ内のタブ同士**だけ。OBS のブラウザソースで追従させるのは段階2のオーバーレイ（OBS WebSocket 経由）。
- OBS 連動は開発環境に OBS が無いため、偽の OBS（Playwright の `routeWebSocket`）で Hello/Identify/CallVendorRequest の往復と、受け取ったイベントを各パーツへ `window.dispatchEvent` で配る形で E2E を確認した。本物の OBS（obs-browser の emit_event・Chrome の「デバイス上のアプリ」許可の出方）は実機で確認が必要。
- 進行画面のタブを閉じる・スリープすると送信が止まる（パーツは最後の表示のまま）。
- X 埋め込み・実画像は開発環境から X に接続できないため実機で確認が必要。
- 速さ（実データ 10/31 配信の週・963 件、開発機の Chromium）: 描画 約 10〜15ms、一般のバズ「すべて表示」（777 行）約 15〜20ms、検索 約 15〜25ms、選択 約 30〜45ms、編集 1 回（話題の作り直し＋保存＋描画）約 30〜35ms、元に戻す 約 35ms。埋め込みはプレビュー（と仕分けモード・進行・映す用）の 1 件だけ。
- タッチのドラッグは「⋮⋮」から（行の上ではスクロールを優先）。タッチの自動テストは無く、マウスのドラッグを E2E で確認している。
- データの基準時刻（generated_at）が配信直後（土 1:00 以降）だと、番組週は「来週」になり投稿がほとんど無い。準備中の週を見るときは上の「番組週」で選ぶ（選んだ週は保存される）。
