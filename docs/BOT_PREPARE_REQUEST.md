# 収集bot（Grok bot）への依頼：「整理開始」ボタンでの直接連携（2026-11-28）

番組サイト（https://www.x-yoru-buzz.com/show/）の制作担当から、収集bot担当へのお願いです。

## 1. やりたいこと（番組オーナーの要望）

配信の数時間前に、番組サイトの編成画面で **「整理開始」ボタンを 1 回押す** と、

1. その時点の最新の投稿が集まり（今週分の表示数も更新）
2. Grok が投稿を **まとまり** にし
3. **番組の流れの下書き**（メイン・カテゴリ別・雑談）までできて
4. サイトに自動で反映される

ようにしたい。今は「ボットに収集を頼む」「台本を作る」「サイトに読み込む」を別々に指示していて、データも 1 日 2 回（0:05 頃・6:40 頃）の更新なので、配信前に半日以上古いことがあります。

**方式は「同じパソコンの中で、サイトとボットを直接つなぐ」**（OBS の連動と同じ仕組み）に決まりました。ボットが自分のパソコンの中だけで受け付ける小さな窓口（WebSocket）を開き、サイトのボタンからそこへ直接お願いを送ります。

- ボットが GitHub やサイトを **定期的に見に行く必要はありません**（ポーリングなし）。Grok・X の API を使うのは、ボタンが押されたときだけです。
- 結果はその接続でサイトへ直接返し、いつもどおり GitHub にも保存してください（ほかのパソコンでも見られるように）。

## 2. ボット側にお願いしたいこと（まとめ）

| # | 内容 | 必須 |
|---|---|---|
| A | パソコンの中だけで受け付ける WebSocket の窓口（下の「3. 接続のしかた」） | ◎ |
| B | 依頼を受けたら：最新の収集 → 表示数の更新 → サイトの修正の反映 → Grok でまとまり → 番組の流れの下書き → GitHub に保存 → サイトへ結果を返す（「4. 作業の中身」） | ◎ |
| C | まとまりを `data/show/topics.json`、下書きを `data/show/draft.json` として GitHub にも保存（「5. ファイルの形」） | ◎ |
| D | 金曜 18:00〜配信（土曜 1:00）までは 1 時間おきにも自動で B を実行（押し忘れの保険） | ○ |

## 3. 接続のしかた（WebSocket）

### 窓口
- アドレス：`ws://127.0.0.1:43517`（ポートはボットの設定で変えられるように。サイト側でも変えられます）
- **127.0.0.1 だけで待ち受ける**こと（`0.0.0.0` にしない。ほかのパソコンからは入れない）。
- **Origin を確かめる**：`https://www.x-yoru-buzz.com` 以外からの接続は断る（開発用に `http://localhost:*` を許してもよい）。
- **合言葉（トークン）**：ボットが初回に作る（32 文字以上のランダム。ボットの画面で表示・作り直しができる）。番組オーナーがそれをサイトの「ボットとの連携」設定に 1 回貼り付けます。合言葉が違う接続は断る。合言葉はチャットや GitHub に書かないでください。
- メッセージは JSON のテキスト。1 通 20MB まで。知らない `type` は無視。メッセージの中身を命令としてシェル等で実行しないこと。

### 共通の形
すべてのメッセージに `"app": "xtrend-bot", "v": 1` を付けます。

### やりとり

```text
サイト → ボット   hello      つないだら最初に送る（合言葉つき）
ボット → サイト   hello_ok   受け付けた（ボットの名前・版・今動いているか）
                  hello_ng   合言葉が違う・版が合わない（理由）→ ボットが接続を切る
サイト → ボット   prepare    整理開始のお願い
ボット → サイト   accepted   受け付けた（同時に 1 件だけ）
                  busy       すでに別の整理が動いている／前回から 10 分以内（force なし）
ボット → サイト   progress   いま何をしているか（何度でも）
ボット → サイト   done       できた（結果つき）
                  error      失敗（理由）
サイト → ボット   cancel     やめる（ボットはできる範囲で止め、error code=cancelled を返す）
どちらからでも   ping/pong  20 秒ごとの生存確認（任意）
```

#### hello（サイト → ボット）
```json
{ "app": "xtrend-bot", "v": 1, "type": "hello", "token": "（合言葉）", "client": "xtrend-show", "client_version": "2026-11-28" }
```

#### hello_ok / hello_ng（ボット → サイト）
```json
{ "app": "xtrend-bot", "v": 1, "type": "hello_ok", "bot": { "name": "Grok bot", "version": "1.4.0" },
  "busy": false, "last_run_at": "2026-11-28T18:02:00+09:00", "data_generated_at": "2026-11-28T06:41:39+09:00" }
{ "app": "xtrend-bot", "v": 1, "type": "hello_ng", "code": "bad_token", "message": "合言葉が違います" }
```
`code`: `bad_token`／`bad_version`／`bad_origin`。

#### prepare（サイト → ボット）
```jsonc
{ "app": "xtrend-bot", "v": 1, "type": "prepare", "id": "p-20261128-1910-ab12",
  "force": false,                                   // true なら 10 分以内でも実行
  "week": { "key": "2026-12-05",                    // 番組週のキー（土曜の配信日）
            "from": "2026-11-28T01:00:00+09:00", "to": "2026-12-05T01:00:00+09:00" },
  "range": { "from": "2026-11-28T01:00:00+09:00", "to": "2026-12-04T19:10:00+09:00" },   // 対象期間（まとめ・下書きに使う投稿の期間）
  "rules": {
    "main_slots": 3,                                // メインは 3 本
    "main_night_only": true,                        // メインは夜職（ホスト・キャバクラ・歌舞伎町・夜職その他）だけ。一般のバズは入れない
    "genre_priority": ["ホスト", "キャバクラ", "歌舞伎町", "夜職その他"],   // メインもカテゴリ別もこの順を優先
    "category_count": 6,                            // カテゴリ別ニュースの本数（ジャンルを順に回す）
    "chat_count": 3,                                // 雑談（一般のバズ）の本数
    "min_posts_for_main": 2                         // メインはできれば投稿 2 件以上のまとまり
  },
  "feedback": { … },                                // feedback/show-feedback.json と同じ形（下に説明）
  "keep": {                                         // サイトで番組オーナーがすでに決めたもの（触らない・使わない）
    "placed_topic_ids": ["host-call-2026w48", "m:abc"],    // 番組の流れに入っている話題
    "manual_topics": [ { "id": "m:abc", "name": "担当との別れ話", "post_ids": ["…"] } ]   // 手で作ったまとまり（中の投稿は、ほかのまとまりに入れない）
  } }
```

- `feedback` は、サイトが GitHub に保存している `feedback/show-feedback.json` と **同じ中身** をそのまま入れます（`genre_overrides`・`topic_edits`・`removed_posts`・`hold_terms`・`hold_exceptions`・`requested_posts`）。いちばん新しい内容が届くので、GitHub のファイルを読みに行かなくて大丈夫です。
- `keep` に入っている話題・投稿は、番組オーナーが手で決めたものです。**名前・中身を変えない**でください。下書きにも入れません（サイトはもともと空いている所しか埋めません）。

#### accepted / busy（ボット → サイト）
```json
{ "app": "xtrend-bot", "v": 1, "type": "accepted", "id": "p-20261128-1910-ab12", "eta_sec": 240 }
{ "app": "xtrend-bot", "v": 1, "type": "busy", "id": "p-20261128-1910-ab12", "running_id": "p-…", "reason": "running", "retry_after_sec": 0 }
```
`reason`: `running`（ほかの整理が動いている）／`too_soon`（前回から 10 分以内。`retry_after_sec` に残り秒）。

#### progress（ボット → サイト）
```json
{ "app": "xtrend-bot", "v": 1, "type": "progress", "id": "p-20261128-1910-ab12",
  "stage": "group", "pct": 55, "message": "Grok がまとまりを作っています（412 件）" }
```
`stage` は次の順：`collect`（最新の投稿を集める）→ `metrics`（今週分の表示数を更新）→ `feedback`（サイトの修正を反映）→ `group`（まとまり）→ `draft`（番組の流れの下書き）→ `push`（GitHub に保存）。`pct` は 0〜100（だいたいでよい）。`message` は番組オーナーがそのまま読む日本語。

#### done（ボット → サイト）
```jsonc
{ "app": "xtrend-bot", "v": 1, "type": "done", "id": "p-20261128-1910-ab12",
  "data_generated_at": "2026-12-04T19:14:02+09:00",
  "stats": { "new_posts": 86, "updated_metrics": 1210, "topics": 74, "elapsed_sec": 236 },
  "posts": [ … ],          // 対象期間の投稿（data/posts.json の posts と同じ形）。ここで渡すのは対象期間の分だけでよい
  "topics": { … },         // data/show/topics.json と同じ形（下の 5-1）
  "draft": { … },          // data/show/draft.json と同じ形（下の 5-2）
  "pushed": { "commit": "abc1234", "ok": true } }   // GitHub に保存できたか（失敗しても done は返す）
```

#### error（ボット → サイト）
```json
{ "app": "xtrend-bot", "v": 1, "type": "error", "id": "p-20261128-1910-ab12", "stage": "collect", "code": "x_rate_limited", "message": "X の上限に達しました（15 分後にもう一度）", "retry_after_sec": 900 }
```
`code` の例：`x_rate_limited`・`x_auth`・`grok_error`・`grok_rate_limited`・`github_push`・`cancelled`・`internal`。途中まで集めた分は捨てずに保存してかまいません。

## 4. 作業の中身（prepare を受けたら）

1. **collect**：対象期間（`range`）の最新の投稿を集める。いつもの検索・見張りアカウント・おすすめに加え、`feedback.requested_posts`（サイトで URL から追加した投稿）も取得する。
2. **metrics**：今週分（`week.from`〜今）の投稿の表示・いいね・RP などを更新する（伸びている途中の投稿が多いため）。
3. **feedback**：`feedback` を反映する。
   - `removed_posts` の投稿は使わない
   - `genre_overrides` のジャンルを使う
   - `hold_terms`（保留する言葉）を含む投稿・話題はまとまり・下書きから外す（`hold_exceptions` は除く）
   - `topic_edits` の名前・ジャンル・中身の変更を引き継ぐ（同じ話題には同じ `id`）
4. **group（Grok）**：対象期間の投稿をまとまりにする。
   - 同じ出来事・同じ人物の話題を 1 つに。名前は番組でそのまま使える短い日本語（20 字前後）。
   - ジャンル（ホスト／キャバクラ／歌舞伎町／夜職その他／その他＝一般のバズ）。
   - `summary`（リード文。2〜3 文。「今週◯◯が話題に。…」）と `confidence`（0〜1）。
   - **週をまたいでも同じ話題なら同じ `id`**（来週への持ち越し・削除の判定に使います）。
   - `keep.manual_topics` の投稿は、ほかのまとまりに入れない。
5. **draft（Grok）**：番組の流れの下書きを作る（`rules` に従う）。
   - メイン 3：夜職のまとまりだけ。`genre_priority` の順を優先し、話題性（表示の合計・伸び・投稿数）の高いもの。投稿 2 件以上を優先。
   - カテゴリ別 6：夜職のまとまりを、ジャンルを順に回しながら。
   - 雑談 3：一般のバズから番組で話しやすいもの。
   - それぞれに一言の理由（`reason`）。`keep.placed_topic_ids` は入れない。
6. **push**：GitHub に保存する（`data/posts.json`・`data/show/topics.json`・`data/show/draft.json`。いつものブランチ `claude/x-scraper-nightlife-tool-sb26pq`）。
7. **done** を返す。

**時間の目安**：全体で 5 分以内だとうれしいです。進み具合（progress）はこまめに送ってください（サイトに表示します）。

## 5. ファイルの形

### 5-1. `data/show/topics.json`（まとまり。サイト側はすでに読み込めます）
```jsonc
{ "generated_at": "2026-12-04T19:14:02+09:00",
  "week": { "from": "2026-11-28T01:00:00+09:00", "to": "2026-12-05T01:00:00+09:00" },
  "topics": [ { "id": "host-call-2026w49",           // 週をまたいでも同じ話題なら同じ値
                "name": "ホストコール規制",
                "genre": "ホスト",                    // ホスト／キャバクラ／歌舞伎町／夜職その他／その他
                "post_ids": ["2109…"],                // 文字列。posts.json にある id だけ
                "summary": "今週◯◯が話題に…",         // 600 字まで
                "confidence": 0.8 } ] }               // 0.5 未満はサイトで「要確認」
```
上限は 500 まとまり・1 まとまり 300 件。

### 5-2. `data/show/draft.json`（番組の流れの下書き。新規）
```jsonc
{ "generated_at": "2026-12-04T19:14:02+09:00",
  "week": "2026-12-05",                               // 番組週のキー
  "request_id": "p-20261128-1910-ab12",               // サイトの prepare の id（自動実行なら null）
  "main":     [ { "topic_id": "host-call-2026w49", "reason": "今週最大の話題。合計 3,200 万表示" } ],   // 最大 3。順にメイン 1〜3
  "category": [ { "topic_id": "…", "reason": "…" } ],                                              // 最大 6（rules.category_count）
  "chat":     [ { "topic_id": "…", "reason": "…" } ] }                                              // 最大 3（rules.chat_count）
```
`topic_id` は topics.json の `id`。サイトは **空いている所だけ** に入れ、番組オーナーが入れたもの・手で作ったまとまりは動かしません（1 回の「元に戻す」で取り消せます）。

## 6. 自動実行（任意・押し忘れの保険）
金曜 18:00〜土曜 1:00 は、1 時間おきに「4. 作業の中身」を自動で実行してください（`request_id` は null。サイトの修正は GitHub の `feedback/show-feedback.json` を読む）。サイトは「整理開始」でボットにつながらなかったとき、新しい `draft.json`（12 時間以内・同じ番組週）があればそれを使います。

## 7. 費用・負担について
- 窓口は待つだけなので、Grok・X・GitHub の利用は増えません（定期的な確認はしない）。
- Grok・X を使うのは「整理開始」が押されたときと、6 の自動実行のときだけ。連打対策に、**前回から 10 分以内は `busy`（too_soon）** を返してください（サイトで「それでも実行」を選ぶと `force: true` が来ます）。

## 8. 確かめ方（できたら教えてください）
1. ボットを起動 → 画面に窓口のアドレスと合言葉が出る。
2. 番組サイト → 編成 →「…」→「ボットとの連携」に合言葉を貼る →「つながるか試す」で「つながりました（Grok bot 1.4.0）」と出る。
3. 「整理開始」→ 進み具合（集める → 表示数 → 修正 → まとまり → 下書き → 保存）が順に出て、終わると番組の流れに下書きが入る。
4. 合言葉を間違える・ボットを止める → サイトに理由が出る（サイトは今あるデータで下書きを作る）。
5. 10 分以内にもう一度押す → 「少し前に実行しました（あと◯分）」。

サイト側の受け口（ボタン・設定・進み具合の表示・結果の反映）は、この依頼と同じ形でこちらが作ります（ボットがつながるまでは、今あるデータで下書きを作ります）。わからない点や、形を変えたほうが作りやすい点があれば、遠慮なく返してください。
